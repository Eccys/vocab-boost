# Contributing to the Vocab Wiki

Thank you for your interest in contributing to the Vocab documentation! This guide outlines the process for making contributions to our wiki.

## Getting Started

### Prerequisites

- GitHub account
- Basic knowledge of Markdown
- Familiarity with Git and pull requests

### Process Overview

1. Fork the repository
2. Clone your fork locally
3. Create a branch for your changes
4. Make your edits
5. Submit a pull request

## Content Guidelines

### Writing Style

- Use clear, concise language
- Write in a conversational but professional tone
- Use second person (you/your) when addressing the reader
- Keep sentences and paragraphs relatively short
- Use active voice wherever possible

### Formatting

- Follow GitHub Flavored Markdown syntax
- Use headings properly (H1 for page title, H2 for main sections, etc.)
- Break up content with subheadings for readability
- Use bullet points or numbered lists for sequential steps
- Include code blocks with appropriate language syntax highlighting

### Images

- Place all images in the `/wiki/images` directory
- Use descriptive filenames (e.g., `installation-step1.png` not `img1.png`)
- Add appropriate alt text for accessibility
- Optimize images for web (compress before adding)
- Ensure screenshots are clear and focus on relevant UI elements
- Use diagrams when helpful for explaining complex concepts

## Best Practices

### Creating New Pages

When creating a new wiki page:

1. Use a descriptive filename with hyphens between words (e.g., `Feature-Guide.md`)
2. Begin with a clear title and brief introduction
3. Add the page to the navigation in `README.md`
4. Link to the page from related pages

### Updating Existing Pages

When updating existing content:

1. Maintain the overall structure of the page
2. Ensure your changes are accurate and up-to-date
3. Preserve cross-references and correct broken links
4. Update screenshots if the UI has changed

### Technical Information

- Verify all technical instructions with the latest version of the app
- Include version numbers when documenting version-specific features
- Test code examples to ensure they work as described
- Provide context for API references and code snippets

## Submit Your Contribution

### Pull Request Process

1. Commit your changes with a descriptive commit message
2. Push to your fork
3. Create a pull request against the main repository
4. Fill out the pull request template completely
5. Respond to any feedback from reviewers

### Review Process

The wiki maintainers will review your contribution:

1. Check for technical accuracy
2. Verify style and formatting consistency
3. Test any instructions or procedures
4. Suggest improvements if needed

Once approved, your changes will be merged into the main wiki.

## Need Help?

If you have questions about contributing:

- Open an issue labeled "documentation question"
- Contact the documentation team at docs@vocab-boost.com
- Ask in the #documentation channel on our Discord server

## Recognition

We value all contributions to our documentation. Contributors will be:

- Listed in our [CONTRIBUTORS.md](CONTRIBUTORS.md) file
- Acknowledged in release notes for significant contributions
- Eligible for community contributor badges
